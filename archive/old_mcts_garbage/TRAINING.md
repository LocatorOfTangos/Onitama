# MCTS Training Guide

This directory contains scripts for training a neural network player for Onitama using Monte Carlo Tree Search (MCTS) and self-play.

## Files

- `train_mcts.py` - Main training script with real-time visualization and checkpointing
- `analyze_training.py` - Utility to analyze and visualize training results
- `MCTS_data/` - Directory where training checkpoints, metrics, and data are saved

## Quick Start

### Basic Training (100 iterations, 10 games per iteration):
```bash
python train_mcts.py
```

### Training with Custom Parameters:
```bash
# More aggressive training: more games per iteration, higher learning rate
python train_mcts.py --iterations 500 --games-per-iter 20 --lr 1e-2 --mcts-sims 200

# Fine-tuning: lower learning rate with longer training
python train_mcts.py --iterations 1000 --lr 1e-4 --lr-decay 0.99999

# Quick testing: few iterations for debugging
python train_mcts.py --iterations 10 --games-per-iter 2 --mcts-sims 10
```

### Resume Training from Last Checkpoint:
```bash
python train_mcts.py --resume --iterations 200
```

## Command-line Options

```
--iterations        Number of training iterations (default: 100)
--games-per-iter    Self-play games per iteration (default: 10)
--batch-size        Training batch size (default: 32)
--mcts-sims        MCTS simulations per move (default: 100)
--lr               Initial learning rate (default: 1e-3)
--lr-decay         Learning rate decay per iteration (default: 0.9999)
--data-dir         Directory for checkpoints and metrics (default: MCTS_data)
--resume           Resume from latest checkpoint
```

## Training Data

During training, the following files are created in `MCTS_data/`:

### Checkpoints
- `latest_checkpoint.pkl` - Always the most recent checkpoint with full training state
- `checkpoint_iter_000000.pkl` - Periodic full checkpoints (every 10 iterations by default)
  - Contains: Network weights, replay buffer, metrics

### Metrics
- `training_metrics.csv` - Detailed metrics for each iteration
  - Columns: iteration, avg_loss, value_loss, policy_loss, game_length, win_rate, learning_rate

### Analysis
- `training_report.json` - Summary statistics (generated by analyze_training.py)

## Monitoring Training

### Live Visualization
During training, a matplotlib window shows real-time plots (if your environment supports graphics):
- Average Loss
- Value vs Policy Loss  
- Learning Rate Schedule
- Average Game Length
- Win Rate Over Time
- Summary Statistics

**Note:** If you're training in a headless environment (no display), the script automatically switches to file-based visualization:
- Plots are saved to `MCTS_data/training_plots.png` after training completes
- No graphical window appears, but all metrics are still recorded
- You can view the plots by opening the PNG file or using `python analyze_training.py --plot`

### Analyzing After Training

View training metrics and plots:
```bash
# Show all information
python analyze_training.py --all

# Show summary report
python analyze_training.py --report

# List all checkpoints
python analyze_training.py --list-checkpoints

# Generate plots only
python analyze_training.py --plot
```

## Understanding the Metrics

- **Average Loss**: Combined loss (weighted policy + value loss). Lower is better.
- **Value Loss**: Error in predicting game outcomes. Lower is better.
- **Policy Loss**: KL divergence between MCTS policy and network policy. Lower is better.
- **Game Length**: Number of moves per game. Varies with play strength.
- **Win Rate**: Percentage of games the current player won. Closer to 50% for balanced training.
- **Learning Rate**: Decays each iteration. Affects training step size.

## Recovery from Interruption

If training is interrupted (Ctrl+C), the most recent checkpoint is saved automatically.

Resume training:
```bash
python train_mcts.py --resume
```

The script will:
1. Load weights from `latest_checkpoint.pkl`
2. Restore the replay buffer
3. Restore all training metrics
4. Continue training from where it left off

## Tips for Effective Training

1. **Start with default parameters** - They work well for most cases
2. **Monitor the loss** - Should generally decrease over time
3. **Check win rate** - Should trend toward 50% as the player improves
4. **Adjust MCTS simulations** - More simulations = better quality training data but slower training
5. **Use learning rate decay** - Helps network converge. Default 0.9999 is conservative.
6. **Save checkpoints frequently** - Change `checkpoint_interval` in train_mcts.py if needed
7. **Resume strategically** - Training can resume multiple times for incremental improvement

## Troubleshooting

**No matplotlib window appears / "FigureCanvasAgg" warning:**
- This is normal! The script detects headless environments and automatically saves plots to `MCTS_data/training_plots.png`
- View plots with: `python analyze_training.py --plot`
- Or open the PNG file directly: `MCTS_data/training_plots.png`

**Training is very slow:**
- Reduce `--mcts-sims` to speed up self-play games
- Reduce `--games-per-iter` for faster iterations
- Use a smaller replay buffer if memory is limited

**Loss is not decreasing:**
- Increase `--lr` (learning rate) to 1e-2 or 1e-1
- Make sure `--mcts-sims` is high enough (at least 50)
- Run more iterations

**Out of memory:**
- Reduce `--batch-size`
- Reduce `--games-per-iter`
- Reduce the replay buffer size in train_mcts.py

**Want to restart from scratch:**
```bash
rm -rf MCTS_data/
python train_mcts.py
```
